# Whole-project audit — 2026-11-09 (HL-069)

Christian asked for a read of the entire project: what is broken, inconsistent,
inefficient or no longer needed. What was certain is fixed in HL-069's commit (the
BUILDLOG entry of this date lists it). **This file is the rest** — everything found
and deliberately not changed, because it is a judgement call, needs a device, moves a
pinned digest, or touches a live page. Ordered by how much it matters inside each
group. Line numbers are as of the HL-069 commit.

## A · Behaviour a user could meet

1. **Two doors, one stale snapshot.** `LaborModel.tap` acts on its in-memory records,
   while the intents (Control Center, Action button, Siri, the Live Activity button)
   write through their own container, and the app only `refresh()`es when the scene
   becomes active. A contraction started from a door while the app is on screen is
   invisible to the model until then; Undo in that window can remove the other door's
   record. Needs a device to see and a decision on the fix (observe the store, or
   refresh on intent).
2. **Live Activity replacement** — *fixed in HL-069, unverified on a device.* The
   sweep that ended stale activities ran after the replacement had been requested and
   could end the one it had just made room for. It now names the stale set first.
   Compiles and the suites pass; an Activity cannot be exercised in the package tests.
   Check on a phone: start, let the activity need replacing (rule change), confirm one
   activity remains.
3. **`ForTheCallButton` and the keyboard counter.** The sheet's `@State isPresented`
   plus `keyboard.sheet` increment/decrement can lose the decrement when the view's
   identity changes while the sheet is up — the counter sticks above zero and Space,
   ⌘J and ⌘G stay disabled until relaunch. iPad with a keyboard only.
4. **Sheets and dialogs that never register with `KeyboardIntents`** — the keepsake
   sheet, `ClearHistoryConfirmation` (two sites) and History's confirmation dialog. Space
   behind them still starts a contraction.
5. **⌘Z replaces the system's undo** and is not gated on `timerIsFrontmost`: editing
   the provider number and pressing ⌘Z undoes a contraction instead of the typing.
6. **`restNote` dropped in one partial-line branch** (TimerScreen ≈1518–1532): the
   early-irregular note does not print in one of the branches that its siblings print it in.
7. **Intent strings without translations.** "Open Hushlight to time this one." and
   "Start or stop a contraction" are not in the catalog `.main` reads, so they speak
   English in the eight other languages. `AppShortcuts.xcstrings`: the second phrase's
   translations sit under a stale key, and the first is `needs_review` in eight languages.
8. **`mergeWithPrevious`** does not guard an earlier record that is still running or
   that ends after the later one.
9. **`deleteFlagged` partial failure** leaves no undo for the rows that did go.

## B · The QA harness (decision 0021)

10. **The simulator picker lands on the iPhone Duo.** `newest-sim.sh iPhone` takes the
    newest runtime's iPhone, and on this machine iOS 27.1 carries only the Duo. `simctl
    io screenshot` refuses a two-display device without `--display`, so `labor-sim.sh`
    photographed **nothing** and said so only as "0 shots" (HL-069 makes that fail the
    stage). `build.sh`, `test.sh`, `pseudo-check.sh` and `walk-gates.sh` pick the same
    device. Decide: exclude the Duo unless asked for, or pass `--display`. Until then
    `HUSHLIGHT_SIM=<a single-display iPhone>`.
11. **`ScaleBenchTests` P99 (F-0054) failed again** in this audit's harness run (and
    passed in two `test.sh` runs the same evening). Since HL-069 a red engine run fails
    `labor-sim.sh`, so this flake now costs a rerun. Gate it, widen it or fix it.
12. **`--ui` cannot fail the run** (`ui_pass` returns 0 on "UI FAILED"), runs the whole
    bundle rather than `ContractionMechanicsTests`, and its summary formats only that one
    class. Left alone because the bundle is red on iOS 27 (HL-067): making it count now
    would make every `--ui` run fail.
13. **The BLOCKED paths return 0** "(SP-042a-class)" although SP-042a is closed — an
    install or launch failure reads as a pass.
14. **T0-13 cannot fire** (HarnessSupport.swift ≈431): it reads the oracle after a
    `hasPattern` guard the oracle fails in exactly the stale case; the staleness is
    caught as T0-02 instead.
15. **The battery brackets the wrong duration line.** `durationExactly59` is tagged the
    "missed side", but since decision 0023 the evidence threshold is 50 s, so 59 s is
    met; there is no 49/50 pair. `zeroLengthContraction` is tagged "legal, not suspect"
    and since 0032 it is a slip. Both tags live in the manifest, so fixing them moves
    the pinned corpus digest. Three battery cases are byte-identical streams under
    different names (`exactlyThreeUsableDurations` ≡ `exactlyTwoIntervals`, etc.).
16. **`fourteenScenariosArePromoted` cannot fail** — every searched pick has a `??`
    fallback, so the count is fourteen whether the searches found anything or not.
17. **`labor-report.swift` reads fields nothing writes:** `falseMetClause`,
    `ScenarioResult.expectedDetection`, a `bench/` directory and `t2`, and the mutation
    logs at `/tmp/mutant-retry.log` / `/tmp/inplace-matrix.log`. Four report sections
    permanently print their "not present" stub. The noise-delta section skips rows with
    no onset delta *before* counting "suppressed outright", so the severe half of T1-05
    is never counted (read, not run).
18. **`labor-mutate.sh` counts any nonzero exit as KILLED** — a compile error or a
    flaky bench included — and never runs an unmutated baseline.
19. **`--deep` does nothing** (`LABOR_QA_DEEP`, `ScenarioCorpus.deep` have no reader),
    yet the report stamps the run "deep".
20. `manifest.json` says generator 3.1.0, `ManifestSchema.generator` and the goldens say
    3.0.0. `T0-10a` is emitted by the code and absent from RUBRIC. Physiology clamps true
    durations to 15–150 s while 15–19 s is now suspect, and the "true physiology never
    manufactures a suspect" test checks only the long side. `OracleSelfTests` has no
    <20 s, trend or stretch case. `w1FlappingIsCounted` asserts zero flaps. Nothing tests
    churn at 6 vs 7 per hour. Schema never exercised: `ruleChanges`, `.setRule`,
    `simulatorCheckpoint`. `TruthSpan.contains` looks unused.
21. `docs/qa/reports/latest.md` is from 2026-08-17 and links untracked shots.
    `walk-gates.sh` is called by nothing and listed nowhere.

    `head -1` of every `DerivedData/Hushlight-*` — with several worktrees that can be
    another checkout's binary.
29. `lint-row-figures.sh` skips `HushlightWidgets`; `lint-loc-catalog.sh` omits
    `AppShortcuts.xcstrings`; CI's gate has no ComponentMatrix preview check; `gate.sh`
    compiles twice; `resolve_device` is duplicated across the shoot scripts.
30. No Duo framing script or `frames-duo/` — the Duo store frames are by hand.
31. `labor-sim.sh` runs `build.sh` and then up to four `xcodebuild test` invocations

    regenerated per suite. The app re-runs `PatternAnalysis.episodes` per render, and
    `pattern()` evaluates `rawPattern` at `now` twice and re-splits history per sample.
    None measured.
